# 图片：GPT Image v2.5

## 先选 slug（四选一）

| 想要 | slug | 说明 |
|---|---|---|
| 从文字出图，日常 | `gpt-image-v2-5-flare-text-to-image` | **默认选它**。快、质量够用 |
| 从文字出图，要极致细节 | `gpt-image-v2-5-sunburst-text-to-image` | 更细，更慢 |
| 改一张已有图 | `gpt-image-v2-5-flare-edit` | 只动被点名的地方，主体/构图不飘 |
| 改图，要极致细节 | `gpt-image-v2-5-sunburst-edit` | 同上，更细更慢 |

两档**参数完全一样**，只差快慢与精细度。先 Flare，不够再 Sunburst。

## 图像专属的一个坑：参数名

**文生图叫 `size`，编辑叫 `image_size`。** 这是两份 schema 唯一的差异。
`additionalProperties: false`，名字传错直接 400，**而错误信息不会告诉你传错了哪个**。
脚本替你兜住了这一条。

（另外三条坑 —— `output` 形状、429 并发闸门、SSL 瞬断 —— 是全平台共有的，见 SKILL.md。）

## 改图可以喂**多张**源图

`image_urls` 最多吃 **16 张**。这条很有用：**一张定身份、一张定画法**。

实测场景：要给已定稿的角色画应用图标。文生图靠文字描述重画她，脸必漂；
改用 edit 模式喂两张 —— 角色立绘 + 游戏真实盘面截图 —— 出来的角色与立绘逐一对得上，
画风也跟游戏同源。

**已经定稿的东西，不要让模型凭描述重画。**

## 不要让模型「把已有画面画进去」—— 它会重画

要做「手机模型里放一张产品截图」这类海报时，最直接的做法是把截图喂进去让它合成。
**实测它会把画面重新画一遍**，画得很像，但不是原图：

| 指标 | 值 |
|---|---|
| 框内宽高比 vs 原图 | 0.514 / 0.460 |
| 逐像素平均差 | **34.4 / 255** |
| 64×64 灰度相关系数 | **0.570**（真拷贝应 >0.98） |

并排看：布局小了一圈、元素换了行、边框上的色块排布全不一样。
对商店截图这类**必须如实呈现**的场合，这是硬伤。

**做法是留色键**：让模型只画海报与设备外壳，**屏幕留成纯品红 `#FF00FF` 空板**，
出图后扫键色定矩形、把原始像素**机械贴进去**，再逐像素复验差为 0。

配套的四道量化闸门（都是踩出来的）：

| 闸门 | 判据 | 起因 |
|---|---|---|
| 有没有画外壳 | 键区 ≤88% 宽 | 两张把键区铺满整幅、根本没画设备 |
| 高度与顶边 | ≤78% 高 且顶边 ≥12% | 一张 75%×85% 顶到 1.7%，标题直接压在画面上 |
| 亮不亮 | 框外均亮 ≥125 | 两张出成深棕木底，缩略图里发闷 |
| 是不是真像素 | 框内逐像素差 = 0 | 见上 |

> **模型不理会提示词里的尺寸要求。** 实测屏幕占宽在 42%–100% 之间乱跳。
> 与其反复改提示词，不如**按键区位置机械裁切**，比例由代码定死。

## 提示词要点

- **图上要出字**：原文用英文双引号裹起来，并点名字体气质（`bold serif` / 条幅粗黑体）。
  v2.5 的文字渲染很稳 —— `quality=low` 出的 "EACHLABS 2.5" 卡片一个字符都没糊。
- **构图**：主体、取景、镜头、光线分开写，别堆形容词。
- **写实**：给物理线索（「45° 斜射硬光，边缘衰减柔和」）比写「高质量、大师作品」有用。
- **改图**：把**不许变的东西**写清楚 —— 「杯子的角度、标签朝向、玻璃上的反光保持完全一致，只换背景」。
- **方向要钉死**：实测模型会把「平板」画成横屏。要竖屏就写
  「clearly TALLER THAN IT IS WIDE, roughly 3 wide by 4 tall, NOT landscape, NOT square」。
- **一次出一套**：把提示词切成「共享 STYLE 段 + 每张一句主体」，共享段**逐字复制**到每条前面。
  失败模式是「这一组不像一套」，而单看一张看不出来。详见
  [batch-recipes.md](batch-recipes.md)。

### 透明背景要**显式否定衬底**

`--background transparent` 给的是真 alpha，但模型仍会自作主张垫一张圆角卡片或一块地面。
要在提示词里点名否定：

```
Single centred object filling the frame, NOTHING else. Completely transparent
background, no backdrop, no ground, no shadow plane, no rounded-square card behind it.
```

和 `codex-image` 不同，这里**不是**绿幕抠图，主体可以含绿色。

> 原生透明的产出常带一层**极淡的 alpha 雾**（值 1–20）。判空时别用 `>0`，
> 用 `>=128` 之类的阈值；`Image.getbbox()` 在 RGBA 上看的是四个通道，
> 而透明像素仍保留 RGB —— 直接用它会得到整幅画布。

## 省钱与提速

- `quality=low` 先出草稿定构图，满意了再用同一段提示词跑 `high`/`xhigh`。
- 实测 low 的 1024×1024 中位 **$0.0066 / 9.3 秒**（n=34）。
- **但别默认「low 只是草稿」** —— 一次 16 张商店图标全用 low，**一张没返工**直接上线。
- **编辑比文生图贵约 4 倍、慢约 2 倍**，能重出就别改。

## 尺寸

枚举值：`1024x1024` / `1536x1024` / `1024x1536` / `2048x2048` / `2048x1152` /
`3840x2160` / `2160x3840` / `auto` / `custom`。

自定义尺寸的约束：**两边都是 16 的倍数**、最大边 ≤3840、宽高比在 1:3 与 3:1 之间、
总像素 655,360–8,294,400。

一个实践：目标尺寸不是 16 的倍数时（比如 1320×2868），取最接近的合法尺寸
（1328×2880，宽高比误差 0.19%）再机械缩放，误差看不出来。

> 注意文档里写的「最大边 ≤3840」不等于任意组合都收：实测 `2560x3840` 被拒
> （`input was rejected as invalid`），而枚举值 `2160x3840` 正常。**拿不准就用枚举值。**
