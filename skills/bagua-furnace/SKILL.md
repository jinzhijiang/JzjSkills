# Codeg「内五行 · 外八卦」多智能体炼丹炉 (Bagua Furnace)

**太极为炉（主会话），五行为火（5 个常驻助手），八卦为方（8 种工作流配方）。**

每个五行助手均具备完整的基础开发能力，同时拥有正交的**主责、判断倾向、五项契约与纠偏义务**。主会话（太极）负责根据任务阶段（旺衰消长）与协作状态（生克制化、乘侮、通关、补偏救弊），通过 `delegate_to_agent(assistant_id=...)` 调度炉内的 5 个五行助手。

### 每个助手的「五项约定」契约结构
`references/{mu,tu,jin,shui,huo}.md` 均严格包含以下五项约定：
1. **约定一**：依赖什么输入，信息不足时如何处理。
2. **约定二**：向谁交付什么（`evidence.md` / `plan.md` / 实现回执 / `ledger.md` / 分级审查结论），什么程度才算完成。
3. **约定三**：接受哪些约束，意见冲突时依据什么判断（验收条件 + 实测证据）。
4. **约定四**：如何识别自身过度（太过/相乘）或不足（不及），何时调整工作方式。
5. **约定五**：何时交接或退出，避免重复调查、循环争论和无限扩展。

### 提示词版本化与同步命令 (`scripts/sync_assistants.py`)

```bash
python3 ~/.claude/skills/bagua-furnace/scripts/sync_assistants.py --export  # 从 codeg.db 导出覆盖 5 个文件
```

## 二、 五行深层协作机制：生克、乘侮、母子、通关、补偏救弊

| 概念 | 传统含义 | 对 Codeg 五行助手协作的工程映射与触发规则 |
| :--- | :--- | :--- |
| **生克制化** | 生与克相互配合，维持整体协调 | **相生链**：`水（洞察）→ 木（设计）→ 火（实现）→ 土（工程承载/账本）→ 金（审查）→ 水`。<br>**相克链**：水克火（实证约束盲改）、火克金（实测/截图破教条）、金克木（风险收敛防膨胀）、木克土（架构演进破守旧）、土克水（账本边界防发散）。 |
| **相乘** | 沿相克方向约束过度 | **金乘木/火**：金把所有设计探索或代码品味偏好都当风险，导致方案/实现无法落地。<br>👉 **纠偏**：金必须区分**阻断项 `R1..`（Must-fix）**与**可选建议 `S1..`（Optional）**，严禁因 `S` 项判 `REJECT`。<br>**木乘火/土**：木把实现细节写死成机械指令。<br>👉 **纠偏**：木 `§4` 只定目标、边界与参考模式，留出实现空间。 |
| **相侮** | 逆相克方向发生反向侵犯 | **木侮金 / 火侮金**：设计或实现助手因坚持己见而拒绝审查或无视门禁。<br>👉 **纠偏**：冲突一律由「`plan.md §5` 验收条件 + `ledger.md` 实测证据」裁决，不凭角色地位裁决。 |
| **母病及子** | 问题沿相生方向向上游传递到下游 | **水病及木 / 木病及火**：水漏查调用链导致木定错方案，或木的需求/设计有误传给火去实现。<br>👉 **纠偏**：发现上游输入有误立即回溯上游，绝不只在下游打补丁掩盖。 |
| **子病及母** | 下游问题反向影响并推动上游修正 | **火/土病及木**：火在实现中发现方案不可行，或土在构建/codegen 中发现契约冲突。<br>👉 **纠偏**：立即停手，将具体限制（`路径:行` 或构建报错）反馈给 `@木 修订` 设计。 |
| **通关** | 双方僵持时，引入连接双方的中间行破局 | **金木相战，以水通关（金生水 → 水生木）**：当 `@金` 与 `@木/@火` 争论某设计是否危险、静态读码无法定论时，禁止来回打嘴仗，派 **`@水 洞察：通关`** 查实际调用链并构造最小实验测试，依据实验结果调整方案。<br>**火金相争，以土通关（火生土 → 土生金）**：当实现与审查对基线或构建状态有分歧时，派 **`@土`** 跑全量集成并刷新 `ledger.md`。 |
| **补偏救弊** | 缺什么补什么，动态调整各行参与度 | • **久议不决（水/木过重，分析瘫痪）** → 派 **`@火 破局`** 推进最小可运行实现；<br>• **代码狂飙缺验证（火过旺）** → 加强 **`@土 工程`**（跑全量基线与 `ledger.md`）与 **`@金 审查`**；<br>• **反复返工迷失方向（火/金死磕）** → 回 **`@木 修订`** 重新收敛目标或 **`@水 通关`**。 |

## 二点五、 中医五行脏腑病机与五运六气在多 Agent 协作中的映射

源自《中医术语一点通》的脏腑生克病理与五运六气（君火/相火），用于精准识别并纠偏五方协作中的隐性失衡：

| 术语 | 传统脏腑病机 | 多 Agent 协作病态（证候） | 工程防治与调理铁律 |
| :--- | :--- | :--- | :--- |
| **木喜条达**<br>`木郁化风 / 木郁化火` | 肝主疏泄，喜调和畅达；肝郁血亏则生虚风（眩晕震颤），郁久内热则化火（暴躁狂乱） | **设计抑郁或暴走**：`@木` 方案摇摆不定、未确认假设满天飞（化风）；或自己想不通架构边界，急躁地出个空洞施工单甩给 `@火` 硬撞（化火） | `plan.md` 未确认假设限 `≤2` 条；条理未通、边界未明时严禁强行派工，先疏通需求或派 `@水` 探路。 |
| **水不涵木** | 肾阴虚不能滋养肝木，致肝阴不足、虚风内动 | **无事实支撑的空想设计**：`@木` 在缺少代码事实或 `evidence.md` 滋养时闭门造车 | 凡排障无证据、或新特性涉及存量黑盒（未确认假设 `≥3` 条），必须先由 `@水` 探路涵木（水生木）。 |
| **水火既济**<br>`水亏火旺 / 水火不济` | 心火与肾水须上下相交；肾水亏则心火独亢妄动，心火妄动又下伤肾阴 | **盲目编码（虚火妄动）**：`@火` 不看 `evidence.md §4/§5` 的调用链与修复约束就凭直觉大改；或 `@水` 的调查脱离实际实现需求 | `@火` 施工前必以 `@水` 的代码地图与约束校准；实现中途遇黑盒崩溃立即停手求 `@水` 济火。 |
| **少阴君火 vs 少阳相火** | 君火在上位主明照神明；相火在下位奉命温煦脾土，妄动则为贼邪 | **实现失度**：常规任务里擅自造新框架（相火妄动），或核心/视觉攻坚里敷衍了事（君火不明） | `plan.md` 表头明定火候：**君火**用于核心算法与 UI 视觉截图自验（≤6 轮）；**相火**用于奉命沿用既有模式高效落码。 |
| **火不生土** | 命门火衰，脾胃失于温煦，水谷不化 | **生冷半成品甩锅**：`@火` 只写业务代码却不写/不跑局部单测与语法检查，把编不过的半成品直接甩给 `@土` | `@火` 交 `@土` 前必须亲自跑通新增单测与语法检查（以火温土）；`@土` 遇生冷半成品直接退回 `@火` 温煦。 |
| **土生万物 & 土喜温燥**<br>`土不制水` | 脾胃为生化之源，喜温燥健运；脾虚湿困则不能制水，致湿浊停滞 | **工作区脏乱与账本瘫痪**：临时文件未删、历史挂掉的测试与新增失败混成一团、调查支线无限发散 | `@土` 保持工作区温燥净空，严格分离「基线已挂」与「新增失败」写入 `ledger.md`；用唯一主线克制 `@水` 的无边界发散。 |
| **木火刑金**<br>(`火盛刑金`) | 肝火与心火过旺，联手耗伤肺金，致肺失清肃 | **海量改动的暴力冲关**：`@木` 摊子铺得极大（>8 步）且 `@火` 顺手重构产生超量 diff（>1200 行），冲垮 `@金` 的上下文与审查能力 | `@木` 超过 8 步必须拆批；`@火` 严禁越出 `§3` 顺手重构；`@金` 遇超量未分批 diff 有权只审高危核或判 `UNCLEAR` 退回拆批。 |
| **金气肃降**<br>`金寒水冷 / 子盗母气` | 肺金主宣清下降；若肺肾虚寒则金寒水冷（消极凝滞），肺虚累脾则子盗母气 | **挤牙膏审查与消极空转**：`@金` 多轮挤牙膏挑刺（肺气上逆），或与 `@水` 反复推诿调查不产代码（金寒水冷），或无故令 `@土` 重复跑全量构建（子盗母气） | `@金` 审查须清肃明快、一次说透；`@土` 的 `ledger.md` 已备齐证据时直接采信（防子盗母气）；`@水 通关` 同一任务限 `1` 次（防金寒水冷）。 |

## 四、 外八卦：8 种工作流配方（后天八卦序 × 先天对偶）

主会话（太极）按任务形态选择以下 8 种配方之一，通过 `delegate_to_agent` 调度。各助手在共同事实账本 `ledger.md` 与 `plan.md` 上协作。

### 配方 1：震卦 ☳（帝出乎震 · 最小原型与破局方）
- **先天对偶**：巽 ☴ ｜ **主导五行**：火旺 → 土相（补偏救弊：治「久议不决」或做快速打样）
- **适用场景**：任务长期停留在分析阶段需最小实现破局、UI 视觉快速打样、或目标与边界已极其明确的轻量直修。
- **标准链路**：
  1. 派 **火 (`assistant_id=5`)** `破局：<一句话目标>`（附允许改动路径与验收条件）；
  2. （若涉多文件或生成物）派 **土 (`assistant_id=2`)** `工程` 跑基线并建 `ledger.md`；
  3. 派 **金 (`assistant_id=3`)** `审查`（区分 `R` 阻断与 `S` 建议）。

### 配方 2：巽卦 ☴（齐乎巽 · 深入洞察与探路方）
- **先天对偶**：震 ☳ ｜ **主导五行**：水旺 → 木相
- **适用场景**：摸底存量架构、查清复杂调用链、评估改动影响面。
- **标准链路**：
  1. 派 **水 (`assistant_id=4`)** `洞察：探路｜<具体问题>`；
  2. 水产出 `evidence.md`（含精确 `路径:行` 代码地图与推动行动的建议），太极直接向用户汇报或按需转入 `@木 定方案`。

### 配方 3：离卦 ☲（相见乎离 · 明案设计与实现方）
- **先天对偶**：坎 ☵ ｜ **主导五行**：木旺 → 火相 → 土集成 → 金审查
- **适用场景**：新功能开发、复杂核心逻辑改造、需要多轮视觉截图自验（`visual-verify.md`）的特性。
- **标准链路**：
  1. 派 **木 (`assistant_id=1`)** `定方案：<目标>` 产出 `plan.md`（写明 `§0 目标与动机`）；
  2. 派 **火 (`assistant_id=5`)** `施工：<plan.md路径>` 完成功能编码、单测与视觉截图（若发现方案不可行，触发「子病及母」回 `@木 修订`）；
  3. 派 **土 (`assistant_id=2`)** `工程：<plan.md路径>` 跑 codegen、格式化、全量测试与跨端构建，产出 `ledger.md`；
  4. 派 **金 (`assistant_id=3`)** `审查：<plan.md路径>｜账本 <ledger.md路径>`。

### 配方 4：坤卦 ☷（致役乎坤 · 工程承载与规整方）
- **先天对偶**：乾 ☰ ｜ **主导五行**：土旺 → 金相（补偏救弊：治「代码狂飙缺验证 / 账实不符」）
- **适用场景**：代码持续增加后需要全面对账与集成验证、维护共同事实账本 `ledger.md`、执行 codegen/多语言同步/资源登记/跨端编译检查等确定性工程任务。
- **标准链路**：
  1. （若尚无方案）派 **木 (`assistant_id=1`)** 出轻量工程单；
  2. 派 **土 (`assistant_id=2`)** `工程：<plan.md路径>`（或 `承载：<主题目录>`）执行全套工程化检查、分离基线失败、更新 `ledger.md`；
  3. 若土发现业务层失败退回 `@火 返工`；若全绿则交 **金 (`assistant_id=3`)** `审查` 放行。

### 配方 5：兑卦 ☱（说言乎兑 · 冲突通关与澄明方）
- **先天对偶**：艮 ☶ ｜ **主导五行**：金/木/水联动（**核心机制：以水通关、分级审查**）
- **适用场景**：
  - **场景 A（金木/火金僵持，以水通关）**：`@金` 与 `@木` 或 `@火` 对某项设计或实现是否安全争执不下 → 派 **水 (`assistant_id=4`)** `洞察：通关｜<争议命题>｜施工单 <plan.md路径>`，由水查实际调用链、写最小实验，再依实验结果交 `@木 修订` 或 `@金` 放行。
