# Codeg「内五行 · 外八卦」多智能体炼丹炉 (Bagua Furnace)

**太极为炉（主会话），五行为火（5 个常驻助手），八卦为方（8 种工作流配方）。**

当前主会话即「太极（炉本体）」，不占卦位与助手槽位，负责识别任务所处阶段（月令），按**外八卦 8 种配方**与**五行旺相休囚死**通过 `delegate_to_agent(assistant_id=...)` 调度炉内的 5 个五行助手。

### 提示词版本化与同步命令 (`scripts/sync_assistants.py`)
五个助手的完整系统提示词与元数据保存在 `references/{mu,tu,jin,shui,huo}.md` 中，修改文件后可通过脚本一键同步进 Codeg 数据库：
```bash
python3 ~/.claude/skills/bagua-furnace/scripts/sync_assistants.py --check   # 校验 5 个文件与 codeg.db 是否一致
python3 ~/.claude/skills/bagua-furnace/scripts/sync_assistants.py --apply   # 将 5 个文件的改动写入 codeg.db
python3 ~/.claude/skills/bagua-furnace/scripts/sync_assistants.py --export  # 从 codeg.db 导出覆盖 5 个文件
```

## 二、 五行生克制化与「乘侮胜复」异常处理律

### 1. 五行相生（正向交接链）
- **水生木**：`@水`（`assistant_id=4`）产出 `evidence.md` → 下一棒交 `@木 定方案` 或 `@木 修订`（`assistant_id=1`）。
- **木生火 / 木役土**：`@木` 产出 `plan.md` → 复杂/核心/视觉交 `@火 施工`（`assistant_id=5`），常规/照抄交 `@土 施工`（`assistant_id=2`）。
- **火生土（升级破局）**：`@土` 施工命中 `E1–E4`（无现成写法、连败 2 次、需看渲染、引用 ≥5 处未列全）时立即停手 → 下一棒交 `@火 接手`（`assistant_id=5`）。
- **土/火生金**：`@土` 或 `@火` 完成自验产出回执 → 下一棒交 `@金`（`assistant_id=3`）验收。
- **金生水 / 金返木**：`@金` 验收放行；缺证据令补证，命中高危 `T1–T5` 升 `@木 终审`。

### 2. 五行相克与制化（防越界）
- **木克土**：`@土` 严守 `plan.md` 的 `§2 决策`、`§3 授权`、`§4 步骤`，禁止擅自设计或扩权。
- **水克火**：`@火` 受 `evidence.md §5 修复约束` 与 `plan.md §3` 限制；缺崩溃数据或需大范围摸底时停手交 `@水 侦察`。
- **火克金**：涉及渲染与视觉时，由 `@火` 跑 `visual-verify.md` 截图自验（≤6 轮）；`@金` 不跑模拟器，只凭截图与数值清单核验。
- **金克木**：`@金` 发现施工单 `§5` 无法验证、`§3` 漏路径或 `§4` 与代码事实冲突，判 `UNCLEAR` 令 `@木 修订`。
- **土克水**：进入明确施工期后禁无故发散重开探路；`@水` 严守 `≤60` 行证据包与收尾 `git status --short` 净空纪律。

### 3. 相乘、相侮与胜复（自动纠偏与熔断）
- **防「木旺乘土」（方案脱离代码事实折腾执行者）**：
  - 事前拦截：`@土` 或 `@火` 开工发现 `§4` 与代码事实冲突或需动 `§3` 未授权路径，不动手，直接回 `@木 修订`。
  - **胜复调节（子复母仇，T5）**：若第 2 轮仍被 `@金` 判 `REJECT`，触发胜复——土/火之子 `@金` 不再派执行者硬磨，直接升 `@木 终审`（金克木），强制裁定是「做法错」还是「方案不成立」。
- **防「土侮木 / 火侮水」（执行者越权反克）**：
  - `@金` 独立运行 `git status --short` 与禁用写法正则扫描，凡越出 `§3 允许改动` 或手改生成物者一律 `REJECT`。
- **防「金旺乘木/土」（无限打回死锁）**：
  - 第 3 轮及以后仍 `REJECT`，触发熔断，下一棒只写「交用户决定」。

## 四、 外八卦：8 种工作流配方（后天八卦序 × 先天对偶）

主会话（太极）根据用户意图选择以下 8 种配方之一，通过 `delegate_to_agent` 依次委派。每次收到助手返回的末行 `下一棒：@<名> <指令>` 时，原样提取并转发给对应 `assistant_id`。

### 配方 1：震卦 ☳（帝出乎震 · 破局直修方）
- **先天对偶**：巽 ☴（雷风相薄）｜**当令五行**：火旺 → 土相（金囚、水死）
- **适用场景**：从 0 到 1 快速原型、UI 视觉调优打样、无需施工单的明确小活（自带目标、验收标准、允许改动路径）。
- **标准链路**：
  1. 委派 **火 (`assistant_id=5`)** 或 **土 (`assistant_id=2`)**（无施工单直修，须在 `task` 给齐目标、验收标准、允许改动路径）：
     ```text
     目标：<一句话目标>
     允许改动：<路径或 glob>
     验收标准：
     - A1【命令】/【视觉】<可观察结果>｜证据：<命令或截图路径>
     ```
  2. 收到回执后，委派 **金 (`assistant_id=3`)** 传入回执全文验收。

### 配方 2：巽卦 ☴（齐乎巽 · 摸底探路方）
- **先天对偶**：震 ☳（雷风相薄）｜**当令五行**：水旺 → 木相（火/土死，严禁改码）
- **适用场景**：搞清楚「某功能是怎么实现的」「改某处会牵连哪里」、评估存量架构。
- **标准链路**：
  1. 委派 **水 (`assistant_id=4`)**：
     ```text
     侦察：探路
     问题：<要查清的代码库问题>
     工作目录：<绝对路径>
     ```
  2. 读取产出的 `evidence.md`（`§3` 答案要点与 `§4` 代码地图），直接向用户汇报，不派施工。

### 配方 3：离卦 ☲（相见乎离 · 明案攻坚方）
- **先天对偶**：坎 ☵（水火不相射）｜**当令五行**：木旺 → 火相 → 金相
- **适用场景**：新功能开发、复杂核心逻辑改造、需要多轮视觉截图自验（动效/布局/主题色）的特性。
- **标准链路**：
  1. 委派 **木 (`assistant_id=1`)** 出施工单（表头定 `执行：火`）：
     ```text
     定方案：<一句话目标>
     背景与约束：<用户原话与涉及端>
     工作目录：<绝对路径>
     ```
  2. 按木返回的下一棒，委派 **火 (`assistant_id=5`)**：
     ```text
     施工：<施工单绝对路径>
     ```
  3. 火完成自验与 `≤6` 轮截图后，将回执全文委派给 **金 (`assistant_id=3`)** 验收。

### 配方 4：坤卦 ☷（致役乎坤 · 顺承施工方）
- **先天对偶**：乾 ☰（天地定位）｜**当令五行**：土旺 → 金相（火待命接手 E1–E4）
- **适用场景**：步骤明确、仓库内有现成写法可照抄的常规功能、CRUD、文案国际化同步、常规修补。
- **标准链路**：
  1. 委派 **木 (`assistant_id=1`)** 出施工单（表头定 `执行：土`，`§4` 写明照抄 `路径:行号`）：
     ```text
     定方案：<一句话目标>
     工作目录：<绝对路径>
     ```
  2. 委派 **土 (`assistant_id=2`)**：
     ```text
     施工：<施工单绝对路径>
     ```
  3. **火生土分支**：若土返回 `升级｜...｜原因：E?`，立即按其末行委派 **火 (`assistant_id=5`)**：
     ```text
     接手：<施工单绝对路径>｜第 1 轮｜原因：E?
     <附土的升级回复全文>
     ```
  4. 拿到回执后，委派 **金 (`assistant_id=3`)** 验收。

### 配方 5：兑卦 ☱（说言乎兑 · 澄明评审方）
- **先天对偶**：艮 ☶（山泽通气）｜**当令五行**：金/木并旺（土/火囚）
- **适用场景**：
  - **兑 A（需求澄清）**：用户需求含糊、存在阻断级产品分歧，先派 **木 (`assistant_id=1`)** 走 `ask_user_question` 澄清并定出 `plan.md`。
  - **兑 B（独立验收/补证）**：工作区已有执行者回执或改动，直接派 **金 (`assistant_id=3`)** 对账审查；若判 `UNCLEAR`，按其去向派 `@土/@火 补证` 或 `@木 修订`。

### 配方 6：乾卦 ☰（战乎乾 · 铁律终审方）
- **先天对偶**：坤 ☷（天地定位）｜**当令五行**：木/金俱旺，火相（全链最高门禁）
- **适用场景**：触碰项目档案 `§5` 危险类别（`T1 持久化格式`、`T2 跨版本协议`、`T3 钱与权益`、`T4 发版与凭据`），或 `T5`（连续 2 轮被金 REJECT 触发胜复）。
- **标准链路**：
  1. （可选）先派 **水 (`assistant_id=4`)** `侦察：探路` 摸清存量兼容边界；
  2. 派 **木 (`assistant_id=1`)** `定方案`（表头标 `终审：需要（T?）`）；
  3. 派 **火 (`assistant_id=5`)** 或 **土 (`assistant_id=2`)** `施工`；
  4. 派 **金 (`assistant_id=3`)** 日常验收，产出 `结论：ACCEPT / ACCEPT-待真机` + `升终审：是（T?）`；
  5. 派 **木 (`assistant_id=1`)** 执行上线前终审（专查不可回滚的坏法）：
     ```text
     终审：<施工单绝对路径>
     <附执行者最新回执全文与金的审查结论全文>
     ```

### 配方 7：坎卦 ☵（劳乎坎 · 探险排障方）
- **先天对偶**：离 ☲（水火不相射）｜**当令五行**：水旺 → 木相 → 土/火施工 → 金验收
- **适用场景**：Countly 线上崩溃、无法稳定复现的疑难 Bug、跨端原生层异常。
- **标准链路**：
  1. 委派 **水 (`assistant_id=4`)** 取证复现：
     ```text
     侦察：崩溃（或 侦察：缺陷）
     <崩溃链接 / group id / 堆栈 / 现象描述>
     工作目录：<绝对路径>
     ```
  2. 若水返回 `建议下一棒：不修`，直接向用户报告原因结束；若返回 `定方案：@木 定方案：...｜证据包 <路径>`，委派 **木 (`assistant_id=1`)** 出施工单（根因已证实且 ≤2 文件时出 `≤40` 行小单）；
  3. 按木指定的执行者委派 **土 (`assistant_id=2`)** 或 **火 (`assistant_id=5`)** `施工`；
  4. 委派 **金 (`assistant_id=3`)** 验收（若有复现测试，金会实跑核验）。

### 配方 8：艮卦 ☶（成言乎艮 · 封版门禁方）
- **先天对偶**：兑 ☱（山泽通气）｜**当令五行**：金/木（发版闸）当令，火/土死（冻结施工）
- **适用场景**：版本发布前守门检查（核对上个 tag 以来所有高危施工单是否均已终审 `ACCEPT`，是否有无单裸改 `§5` 高危路径的提交）。
- **标准链路**：
  1. 委派 **木 (`assistant_id=1`)** 跑发版闸：
     ```text
     终审：发版 <上个 tag，如 V1.2.0>
     工作目录：<绝对路径>
     ```
  2. 若结论为「拦下」，按列出的缺终审施工单或无单高危提交补跑终审；若结论为「放行」，交由主会话或用户执行发版脚本。

## 五、 六十四重卦：常用双助手结对模式速查

当任务只需 2 个助手紧凑配合时，可直接按重卦点名组合：
- **地天泰（坤下乾上 · `木 + 土`）**：架构定单 + 顺承施工（最常用的日常开发搭档）。
- **火天大有（乾下离上 · `木 + 火`）**：顶层方案 + 视觉/核心破局。
- **水火既济（离下坎上 · `水 + 火`）**：火在攻坚中途遇隐蔽缺陷，停手交 `@水 侦察：缺陷｜...｜已有施工单 <路径>`，水取证后火继续破局。
- **火金革（离下兑上 · `火 + 金`）**：无施工单的视觉打样直修 + 截图验收。
- **水木屯（震下坎上 · `水 + 木`）**：先探路摸底产出 `evidence.md`，紧接着立极定出 `plan.md`（只规划不施工）。
